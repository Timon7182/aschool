### Шрифты и иконки (важно при доработках)

Шрифты (Nunito, Manrope) и иконки Material Symbols хостятся локально в `assets/fonts/` —
без обращений к Google Fonts, чтобы не мигал системный шрифт при загрузке.
Файл иконок `material-symbols-rounded.woff2` **сабсечен** — содержит только те ~60 иконок,
которые реально используются на страницах. Если добавляете новую иконку (новое имя в
`<span class="ms">…</span>`), её нужно включить в сабсет: скачайте новый файл по адресу
`https://fonts.googleapis.com/css2?family=Material+Symbols+Rounded:opsz,wght,FILL,GRAD@20..48,300..700,0..1,0&icon_names=<все,имена,через,запятую>`
(в ответе будет ссылка на woff2) и замените им файл в `assets/fonts/`.

## Публикация

Боевой адрес сайта — **https://aschoolastana.kz/** (хостинг на Plesk/nginx, статика лежит
в корне домена). Деплой = выгрузка содержимого репозитория в корень сайта; путь `/aschool/`
на боевом домене не используется.

Все абсолютные адреса в проекте (`canonical`, `hreflang`, `og:url`, JSON-LD, `sitemap.xml`,
`robots.txt`, `llms.txt`) указывают на `https://aschoolastana.kz/`. При смене домена замените
эту строку во всех файлах разом.

### Обязательные настройки на стороне хостинга

1. **301 с `www` на основной домен.** Сейчас `https://www.aschoolastana.kz/` отдаёт `200` —
   это дубль сайта для поисковиков. Нужен редирект `www → aschoolastana.kz`.
2. **Своя страница 404.** Сейчас несуществующий адрес отдаёт стандартную страницу Plesk.
   В настройках сайта включите свой `404.html` (nginx: `error_page 404 /404.html;`).
3. **HTTPS-редирект** с `http://` — уже работает (301), менять не нужно.

### Копия на GitHub Pages

Если репозиторий по-прежнему опубликован через GitHub Pages, эта копия видна поисковикам
как дубль. После деплоя её `canonical` указывает на `aschoolastana.kz`, поэтому склейка
пройдёт корректно, но лучше отключить Pages совсем: **Settings → Pages → Source: None**.

### Смена домена в будущем

Замените `https://aschoolastana.kz/` на новый адрес во всех `.html`, `sitemap.xml`,
`robots.txt` и `llms.txt`, затем переподтвердите сайт в Яндекс.Вебмастере и Google Search Console.

## Яндекс.Метрика — пошаговая настройка

> **Текущее состояние.** Счётчик **111274056** уже подключён и работает: `tag.js` загружается,
> хит `mc.yandex.ru/watch/111274056` уходит с боевого домена, Вебвизор включён.
> Что нужно проверить вручную в интерфейсе Метрики:
> 1. В **Настройка → Общие** поле «Адрес сайта» должно быть `aschoolastana.kz`
>    (если там остался адрес GitHub Pages — исправьте, иначе часть отчётов и связка
>    с Вебмастером/Директом работают некорректно).
> 2. В **Настройка → Цели** должны быть заведены 5 JS-целей из таблицы ниже — без них
>    вызовы `reachGoal` из `main.js` никуда не засчитываются.

### 1. Создание счётчика (если создаёте новый)

1. Зайдите на [metrika.yandex.ru](https://metrika.yandex.ru) (войдите через Яндекс-аккаунт).
2. Нажмите **«Добавить счётчик»**.
3. Заполните:
   - **Имя:** A School
   - **Адрес сайта:** `aschoolastana.kz`
   - **Часовой пояс:** Астана (UTC+5)
4. Включите галочки:
   - **Вебвизор** — запись поведения пользователей на сайте
   - **Карта кликов** — тепловая карта кликов
   - **Карта скроллинга**
5. Нажмите **«Создать счётчик»**.

### 2. Вставка номера счётчика в код сайта

После создания счётчика Яндекс покажет его **номер** — например, `98765432`.

Откройте файл `assets/js/main.js`, найдите строку:

```js
const YM_COUNTER_ID = null; // TODO: вставить номер счётчика
```

Замените `null` на номер вашего счётчика:

```js
const YM_COUNTER_ID = 98765432;
```

После этого Метрика начнёт работать автоматически — код уже встроен в файл.

### 3. Цели для отслеживания конверсий

В интерфейсе Метрики перейдите: **Настройка → Цели → Добавить цель**.

Создайте 5 целей с типом **«JavaScript-событие»** и следующими идентификаторами (скопируйте точно, как написано):

| Название цели                  | Идентификатор (Условие)  |
|-------------------------------|--------------------------|
| Отправка формы                | `form_submit`            |
| Клик по WhatsApp              | `whatsapp_click`         |
| Клик по телефону              | `phone_click`            |
| Клик по соцсети               | `social_click`           |
| Открытие формы записи         | `trial_modal_open`       |

Эти идентификаторы уже используются в коде `main.js` — при соответствующих действиях пользователя цели будут засчитываться автоматически.

### 4. Проверка работы Метрики

Добавьте к URL сайта параметр `?_ym_debug=1`, например:
```
https://aschoolastana.kz/?_ym_debug=1
```
Откройте консоль браузера (F12 → Console). Если Метрика работает, вы увидите сообщения с `[YM]`. Совершите действие (кликните по кнопке «Записаться»), и в консоли появится `[YM] reachGoal trial_modal_open`.

### 5. Связь с Яндекс.Директом

Для корректной аналитики рекламных кампаний:
1. Яндекс.Метрика и Яндекс.Директ должны быть привязаны к **одному Яндекс-аккаунту**, либо вы должны предоставить доступ к Метрике из Директа.
2. В Директе при создании объявлений используйте **разметку ссылок** (опция «Размечать ссылки» в настройках кампании) — это автоматически добавит параметр `yclid` к URL.
3. В `robots.txt` уже прописан `Clean-param` для параметров `utm_*` и `yclid` — поисковик не будет дублировать страницы с рекламными метками.
4. В настройках кампании Директа укажите **ключевые цели** из Метрики — выберите `form_submit` и `whatsapp_click` как конверсионные цели для оптимизации ставок.

## Настройка формы заявок

### 1. Телефон WhatsApp

В файле `assets/js/main.js` найдите:
```js
const WHATSAPP_PHONE = '77004349775';
```
Реальный номер уже внесён. При необходимости замените на новый в формате: `7XXXXXXXXXX` (без `+`, пробелов и скобок).

### 2. Email для дублирования заявок (через formsubmit.co)

В файле `assets/js/main.js` найдите:
```js
const LEAD_EMAIL = 'info@aschool.kz'; // TODO
```
Замените на реальный email, куда будут приходить копии заявок.

### 3. Активация formsubmit.co

При **первой** отправке формы на указанный email придёт письмо от formsubmit.co с просьбой подтвердить адрес. Перейдите по ссылке в этом письме — после этого дублирование заявок на email заработает. Если письмо не пришло — проверьте папку «Спам».

### Как заменить логотип

1. Получите от клиента оригинальный логотип в формате PNG или SVG.
2. Сохраните файл как `assets/img/logo.svg` (или `logo.png`).
3. Если используете PNG, измените в HTML-файлах атрибут `src` у тегов `<img>` с логотипом:
   ```html
   <!-- было -->
   <img src="assets/img/logo.svg" ...>
   <!-- стало -->
   <img src="assets/img/logo.png" ...>
   ```
4. Для favicon: сохраните значок как `assets/img/favicon.svg` (или `.png`) и при необходимости обновите `<link rel="icon">` в `<head>` каждой страницы.

## SEO-чеклист после публикации

### Что осталось сделать вручную (в порядке важности)

1. **Выложить текущую версию репозитория на боевой домен.** До деплоя на `aschoolastana.kz`
   висит старая сборка, у которой `canonical` указывает на GitHub Pages — поисковики считают
   боевой домен копией и не показывают его в выдаче.
2. **301-редирект `www → aschoolastana.kz`** и **своя страница 404** на хостинге (см. раздел «Публикация»).
3. **Подтвердить сайт** в Яндекс.Вебмастере и Google Search Console — мета-тегов
   `yandex-verification` / `google-site-verification` в коде пока нет, добавляются после регистрации.
4. **Отправить sitemap** в оба сервиса и запросить переобход главных страниц.
5. **Проверить цели в Метрике** (см. блок выше) — код их отправляет, но цели должны быть заведены.
6. **Оптимизировать тяжёлые картинки:** `assets/img/hero-girl.png` весит 1,4 МБ и грузится
   первым экраном — пережать в WebP (ожидаемая экономия ~90%). Для соцсетей желательно
   отдельное изображение 1200×630 вместо логотипа 640×701 в `og:image`.

### Яндекс.Вебмастер

1. Зайдите на [webmaster.yandex.ru](https://webmaster.yandex.ru).
2. Нажмите **«Добавить сайт»**, введите `https://aschoolastana.kz/`.
3. Подтвердите владение сайтом — выберите метод **«Мета-тег»**: скопируйте предложенный тег `<meta name="yandex-verification" ...>` и вставьте его в `<head>` файла `index.html`.
4. После подтверждения: **Индексирование → Sitemap-файлы** → добавьте `https://aschoolastana.kz/sitemap.xml`.
5. Проверяйте раздел **«Качество сайта»** и **«Диагностика»** раз в неделю.

### Google Search Console

1. Зайдите на [search.google.com/search-console](https://search.google.com/search-console).
2. Добавьте ресурс — тип **«URL-prefix»**, введите `https://aschoolastana.kz/`.
3. Подтвердите владение (рекомендуется метод HTML-тег: вставить в `<head>` тег `<meta name="google-site-verification" ...>`).
4. Перейдите в **Sitemaps** → добавьте `https://aschoolastana.kz/sitemap.xml`.

### Локальная выдача (карты и справочники)

Для детского центра критически важна локальная выдача — родители ищут «подготовка к школе рядом».

1. **Яндекс.Бизнес** ([business.yandex.ru](https://business.yandex.ru)) — добавьте организацию: название, адрес, телефон, сайт, фото центра, категория «Образовательный центр». После модерации (1–5 дней) центр появится на Яндекс.Картах.
2. **2ГИС** ([2gis.ru/partners](https://2gis.ru/partners)) — бесплатное добавление организации. Популярен в Казахстане, важен для Астаны.
3. **Google Business Profile** ([business.google.com](https://business.google.com)) — заполните профиль: название, адрес, часы работы, фото, ссылка на сайт. После верификации центр появится на Google Картах и в блоке «Local Pack» в поиске.

**Важно:** в профилях всех трёх сервисов используйте одинаковые название, адрес и телефон (NAP-консистентность) — это улучшает ранжирование в локальной выдаче.
